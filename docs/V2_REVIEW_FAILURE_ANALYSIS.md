## Predicate mismatch found in the complete run
At the first 30-record checkpoint, all ten state checks passed, but two of three current-role questions abstained. The planner used `coordinator_of` while the relevant confirmed memories used `coordinator`; a different project's current row used `coordinator_of`, so global predicate validation did not catch the mismatch. The strict filter returned no candidates. A failing-before regression reproduces the mismatch including that other-project vocabulary.

An initially broad fallback failed the existing qualified-identity test; a global-known-slot variant was insufficient for the actual cross-project case. Both intermediate test artifacts are retained. The final fix compares label content after removing grammatical wrappers such as `of` and `is`, preserving non-Latin tokens and all identity/time/lifecycle constraints. It does not merge memories, infer an inverse relationship, or equate unrelated content words. All 76 tests pass for that behavior. The original 500-record process keeps its loaded code and unchanged scores; saved checkpoints support a separate affected-query replay. That replay does not claim to rerun ingestion.

## Evaluation integrity
The first longitudinal baseline was deliberately stopped after 169 of 500 records once concrete failures were established. It is not a complete benchmark: 128/130 scored retention checks, 4/13 questions, 14/40 raw state checks. A separate actor-orientation correction gives 24/40 states because a valid actor may occur at either triple endpoint; the original scores remain unchanged. Independent post-hoc metadata diagnostics passed 25/50 available cases.

The independent corpus was authored without calling or importing the extractor. It interleaves ten project worlds over 50 steps, with 410 scored retention checks, 70 state checks, 44 questions/tasks and 90 additional metadata diagnostics. Its repeated templates provide coverage, not natural-user accuracy. Retention presence is weaker than semantic correctness. Literal answer keys and source recall can reject valid paraphrases; adjudication must remain separate from raw results.

The 16-record corrected pilot has 9/9 answers and 5/5 states. The final native privacy probe has 14/14 checks, including seven HTTP ingestion acceptance checks, six answer checks and one certificate-state check. HTTP acceptance alone is not semantic correctness. The application verifier uses the same model and has demonstrated correlated error; it is part of the tested system, never the source of expected labels.

The first attempt at the corrected 500-record run ended after seven completed records when processes stopped during a session interruption. Its inputs, decisions and partial database exports remain in longitudinal-interrupted-7. The complete run starts from a fresh database, not from that partially committed state.

## Engineering tradeoffs
SQLite remains the transactional store, with in-process cosine scans over model-tagged embeddings. The observed failures concern interpretation, identity, lifecycle and provenance. They do not establish a need for Postgres, a graph database or a vector service. Local inference dominates the observed latency.

Forget means retrieval exclusion with retained audit evidence, not physical erasure. Older unpromoted full transcripts are conservatively excluded after a forget boundary. This protects against raw/vector resurrection at a cost to unrelated historical recall. Forgotten alias names without independent active identity evidence are also conservatively declined until explicitly relearned. Names and binding cues are currently English-oriented.

The full longitudinal result and exact final-clone review evidence are summarized in eval/v2_report.md and the release report. No broad generalization claim should be inferred from unit tests or a small pilot.
